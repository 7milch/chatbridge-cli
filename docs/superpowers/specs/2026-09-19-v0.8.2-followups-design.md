## Section 4: webview, bridge, slash commands (task 3)

### `tookBack` message (protocol change)

Add to `HostMessage` in `protocol.ts`:

```ts
| { type: "tookBack"; entries: QueueEntry[] }
```

`chat-view-bridge.ts` posts it with the array `controller.takeBack()`
returns, before the following `state`. The webview fills the composer only
on `tookBack` (never from `lastState.queue`), so an entry drained between
the last `state` and the Up key cannot be re-sent. The parity spec
(`2026-09-18-vscode-parity-design.md` §1 "Webview") is updated to describe
this.

### Composer auto-resize (#68)

- `<textarea rows="1">`; CSS `max-height` = 8 × line-height,
  `overflow-y: auto`, `resize: none`.
- `fitComposer()`: set `height = "auto"` then `height = min(scrollHeight,
  max)`; called on `input`, after `insertAtCaret` (both paths), and after
  anything that clears the composer (send, `/` command, take-back fill).
  Wrapped lines count because `scrollHeight` is used.
- After a height change, keep the history scrolled to the bottom if it
  was at the bottom before.
- Keep the Send button bottom-aligned with the composer.

### Other webview items (#67, #59-5)

- `/help` becomes a host-side `help` history entry (added by the bridge
  when the slash command resolves), so it survives re-renders.
- `dragleave` uses a depth counter; `dragover`/`drop` `preventDefault`
  only when the drag carries files or URIs; comment on the document-wide
  Ctrl/Cmd+R `preventDefault`.
- `insertAtCaret` fallback dispatches an `input` event; the 500 ms paste
  fallback is skipped when the composer is disabled.
- `button(label, onClick, className?)`.
- Keep the last progress line across re-renders, no `focus()` on every

### Bridge and slash commands

## Section 6: banner colours (task 5, #65)

`CreateCliOptions.banner?: string[] | BannerOptions` where

```ts
export interface BannerOptions {
  lines: string[];
  /** ANSI palette index or "#rrggbb"; omitted = all lines muted. */
  colors?: Array<number | string>;
  /** Default "per-line". */
  mode?: "per-line" | "per-char" | "gradient";
}
```

Resolution (`packages/cli/src/tui/banner.ts`), same shape as
`resolveSpinner`:

- A plain `string[]` behaves exactly as today (all muted).
- `per-line`: line `r` uses `colors[r % n]`.
- `per-char`: cell `(r, c)` uses `colors[(r + c) % n]` (diagonal flow).
- `gradient`: line `r` uses the linear interpolation of `colors` (hex only)
  at position `r / (rows - 1)` across the whole array; a single-line
  banner takes `colors[0]`.
- Validation at `createCli` time: `gradient` requires ≥ 2 colours, all
  hex; `per-line`/`per-char` require ≥ 1 colour. Violations throw an
  `Error` naming the option.
- Implementation: a pure `bannerColorAt(row, col, spec)` returning a
  `SpinnerColor | undefined`, and a chunk assembler that groups adjacent
  cells of the same colour into one `TextChunk` (via the existing
  `colored()`); a small `mixHex(a, b, t)` helper in `theme.ts`. Centering
  width is computed from the plain lines.
- Docs: README banner section and the `creating-provider-repo` skill
  mention the object form with one example.
